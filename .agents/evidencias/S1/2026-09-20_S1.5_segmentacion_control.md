# S1.5 — Control de segmentación mínima

- **Fecha:** 2026-09-20
- **Estado:** Bloqueado
- **Objetivo:** aplicar y comprobar la segmentación L3 mínima: gestión hacia PVE-1/PVE-2 por SSH/HTTPS de Proxmox, backup hacia BKP-1 sólo mediante protocolos acordados e invitados bloqueados hacia redes internas.

## Precondiciones

- [x] Las redes y destinos de diseño están definidos: PVE-1 `192.168.90.20`, PVE-2 `192.168.110.10` y BKP-1 `192.168.160.10`.
- [x] El aislamiento de invitados de VLAN 60 hacia redes RFC1918 fue comprobado en S1.4 mediante `VLAN_60_IN`; no se modifica en esta tarea.
- [x] La API HTTP local de GNS3 responde y el proyecto `PFT-sprint2-preview1` está abierto; el preestado está en `2026-09-20_S1.5_GNS3_pre.md`.
- [ ] Las consolas autenticadas de DistvIOS-1/2 entregan prompt IOS para completar la lectura vigente de adjuntos ACL y HSRP.
- [ ] Protocolos y puertos de backup autorizados entre DC1, DC2, FS-HQ, PVE-1/PVE-2 y BKP-1 definidos explícitamente.
- [ ] PVE-1, PVE-2, BKP-1 y un cliente de gestión activos para pruebas permitidas y denegadas.

## Comandos/acciones ejecutados

1. Se revisaron el plan vigente, el plano ejecutivo, la matriz de segmentación y las evidencias aprobadas S1.3/S1.4.
2. Se consultó por HTTP la versión, proyectos, nodos y enlaces de GNS3. La API respondió `2.2.61`; el proyecto objetivo está abierto. CorevIOS-1/2 respondieron en lectura; las consolas Dist aceptaron conexión pero no entregaron prompt IOS.
3. El inventario HTTP mostró PVE-1/PVE-2/PVE-QDEVICE detenidos y ningún nodo BKP-1.
4. No se creó, adjuntó ni persistió ninguna ACL. No se modificaron SVIs, OSPF, DHCP, NAT/PAT, rutas, VMs ni servicios.

## Resultado

**Bloqueado.** La segmentación de PVE no puede aplicarse de manera segura sin PVE activos, sin confirmar los adjuntos actuales de Dist y sin probar tráfico real. El control de BKP-1 no puede definirse porque el nodo no existe en el proyecto y tampoco están definidos los protocolos/puertos autorizados; el plan prohíbe aplicar ACL con marcadores. El aislamiento de invitados ya verificado en S1.4 se conserva como antecedente, no como cierre de S1.5.

## Rollback

No aplica: no hubo cambios. Al reanudar, guardar el `startup-config` y el adjunto efectivo de cada SVI antes de crear listas. Si una frontera falla, retirar sólo la ACL nueva de esa SVI y reponer su adjunto real de preestado; no modificar OSPF, DHCP, NAT/PAT ni interfaces como rollback genérico.
