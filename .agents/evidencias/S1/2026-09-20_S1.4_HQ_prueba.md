# S1.4 — Prueba de aislamiento de invitados y continuidad NAT

- **Fecha:** 2026-09-20, 04:56–04:57 UTC
- **Estado:** Aprobado con limitación documentada
- **Origen:** `guestPC-1`, zona cowork, VLAN 60.

## Comandos ejecutados

```text
ip route
ping -c 3 -W 2 192.168.60.1
ping -c 3 -W 2 192.168.50.2
ping -c 3 -W 2 192.168.90.2
ping -c 3 -W 2 8.8.8.8
```

Se contrastaron después `show access-lists VLAN_60_IN` en CorevIOS-2 y `show ip nat translations` en BorderRouter-2.

## Resultado

| Prueba | Resultado obtenido | Criterio |
|---|---|---|
| Dirección y ruta de GuestPC-1 | Origen `192.168.60.11`; ruta predeterminada vía `192.168.60.1`. | Conforme |
| Gateway de VLAN 60 | 3/3 respuestas de `192.168.60.1`; promedio 2.913 ms. | Conforme |
| Invitados → VLAN 50 | 0/3 respuestas hacia `192.168.50.2`. | Denegado conforme |
| Invitados → VLAN 90 | 0/3 respuestas hacia `192.168.90.2`. | Denegado conforme |
| Contador ACL | La línea de denegación hacia redes corporativas acumuló 6 coincidencias tras ambas pruebas negativas. | Conforme |
| PAT saliente | El intento a `8.8.8.8` generó una traducción dinámica desde `192.168.60.11` en BorderRouter-2. | PAT preservado |

## Limitación

`8.8.8.8` no respondió (0/3). La traducción PAT demuestra que el tráfico salió por el Border, pero esta evidencia no acredita disponibilidad extremo a extremo de ese destino externo. No se modificó NAT/Internet para compensarlo.

## Conclusión

VLAN 60 conserva aislamiento hacia las redes internas comprobadas y la configuración NAT/PAT existente permaneció sin cambios. La indisponibilidad de la respuesta externa queda como limitación de conectividad, no como cambio ni fallo de S1.4.
