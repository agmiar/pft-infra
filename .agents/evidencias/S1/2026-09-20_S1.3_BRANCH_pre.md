# S1.3 — Preestado BRANCH

- **Fecha:** 2026-09-20
- **Estado:** Pendiente
- **Fuente:** consolas Telnet del proyecto GNS3 `PFT-sprint2-preview1` (`2.2.61`).
- **Contraseña:** no se registra.

## CorevIOS-1/2

`show ip interface brief` confirmó interfaces HQ existentes y tránsito L3 activo:

- CorevIOS-1: `Gi3/0 10.0.5.1/30`, `Gi3/1 10.0.7.1/30`; `Vlan50 192.168.50.2/27`.
- CorevIOS-2: `Gi3/0 10.0.6.1/30`, `Gi3/1 10.0.8.1/30`; `Vlan50 192.168.50.3/27`.

El DHCP local sólo tenía pools VLAN 10, 20, 30, 40, 60 y 90; no existían pools BRANCH. CorevIOS-1 tenía exclusión `192.168.50.1–192.168.50.30`. No había SVIs BRANCH en ninguno de los Core.

## DistvIOS-1/2

Ambos tenían sólo VLAN 1, 10, 20, 30, 40, 50, 60, 90, 99 y 100. No existían VLAN 110, 115, 120, 130, 140, 150 ni 160, ni SVIs, ni `ip helper-address` BRANCH.

- DistvIOS-1: `Gi0/1 10.0.5.2/30` hacia CorevIOS-1 y `Gi0/2 10.0.6.2/30` hacia CorevIOS-2; trunks `Gi1/1` y `Gi1/2` up.
- DistvIOS-2: `Gi0/1 10.0.7.2/30` hacia CorevIOS-1 y `Gi0/2 10.0.8.2/30` hacia CorevIOS-2; trunks `Gi1/1` y `Gi1/2` up.
- OSPF proceso 1, área 10, sólo anunciaba los dos `/30` de tránsito por cada Dist; los vecinos estaban operativos.
- El hostname IOS runtime de DistvIOS-2 continúa siendo `DistvIOS-1`.

## Cableado contrastado por API GNS3

- DistvIOS-1 `Gi1/1` y `Gi1/2` llegan a AccvIOS-1 y AccvIOS-2.
- DistvIOS-2 `Gi1/1` y `Gi1/2` llegan a AccvIOS-1 y AccvIOS-2.
- AccvIOS-1/2 y los clientes de prueba estaban detenidos al capturar el preestado; no se usaron para declarar DHCP comprobado.

## Comandos de lectura

`show clock`, `show ip interface brief`, `show vlan brief`, `show run | section interface`, `show run | section ip dhcp`, `show run | section router ospf`, `show ip route` y `show ip ospf interface brief`.

No se incluyen secretos ni claves OSPF.
