# S2.1 — Incidente durante intento inicial por VNC

- Fecha: 2026-09-20 (UYT, UTC-03:00).
- Tarea: S2.1.
- Estado del intento: Fallido.
- Estado final de S2.1: Aprobado después de repetir el cambio por SSH desde Alpine.

## Síntoma

Durante el primer intento de edición de `/etc/network/interfaces` de PVE-1 mediante VNC, una línea larga de entrada perdió caracteres. El archivo quedó parcial/no confiable y `ifreload -a` no se consideró una aplicación válida.

## Impacto

El intento no acreditó ningún cambio de red. No se perdió la sesión de gestión: la dirección activa continuó en el preestado y se abortó el procedimiento antes de seguir con PVE-2.

## Evidencia

- El preestado runtime está en `2026-09-20_S2.1_PVE_pre.txt`.
- La secuencia de rollback ejecutada está registrada en `2026-09-20_S2.1_PVE_rollback.md`.
- La verificación posterior demuestra que ambos PVE fueron configurados por el procedimiento alternativo SSH y que pasan `ifquery --check -a`.

## Rollback aplicado

En PVE-1 se ejecutó:

```text
cp -a /etc/network/interfaces.s2.1.pre /etc/network/interfaces
ifreload -a
ip -br addr
ip route
```

El estado observado volvió a `vmbr0 192.168.50.10/27` con gateway `192.168.50.1` y `ens4` DOWN.

## Condición de reanudación

Repetir la aplicación usando Alpine-SSHClient-1 y SSH, con copia/pegado del bloque validado. Esta condición se cumplió; no se vuelve a usar VNC para introducir configuración larga.
