# S2.3 — VMs de servicio y clientes Windows GNS3

- Fecha de inicio: 2026-09-20 (UYT, UTC-03:00).
- Estado: Aprobado.
- Objetivo: crear o ajustar DC1, DC2, FS-HQ y ZBX-1 en PVE; crear los dos clientes Windows de gestión como appliances QEMU independientes dentro de GNS3, conservando PVE independientes.
- Criterio de aceptación: inventario real de las VMs de servicio y de cada appliance cliente con estado, recursos, disco/ISO, enlace, VLAN y ubicación por sede; sin clientes Windows dentro del inventario de VMs PVE.

## Precondiciones

- [x] El operador confirmó iniciar S2.3.
- [x] S2.1 está aprobada: bridges de VMs separados de gestión.
- [x] S2.2 está aprobada: PVE-1 y PVE-2 son independientes y no hay HA/replicación activa acreditada.
- [x] El diseño vigente identifica la ubicación y el direccionamiento de los servicios y clientes.
- [x] Acceso administrativo a PVE-2 disponible mediante consola VNC y SSH con credencial proporcionada por el operador.
- [x] Capacidad, almacenamiento y configuración runtime de PVE-2 capturados.

## Comandos/acciones ejecutados

Se usó la consola VNC local de PVE-1 (puerto local 5904), sin registrar credenciales. Se ejecutaron:

```text
date -Is
hostname
qm list
pvesm status
free -h
df -h / /var/lib/vz
qm config 101
```

En PVE-2 se abrió la consola VNC local (puerto local 5900), se autenticó el operador y luego se verificó SSH desde `Alpine-SSHClient-1`. La credencial no se registra.

Se creó el respaldo operativo fuera del repositorio `/root/s2.3-pre-20260920/` en cada PVE. Antes de crear las VMs se conservó la configuración de DC1/VMID 101 y DC2/VMID 102.

Se crearon las VMs de servicio con discos thin locales de 32 GiB, `vmbr0` según sede y los recursos definidos en el inventario. Para que la NIC de datos de PVE-2 llegara a BRANCH/VLAN 115, se retiró el enlace histórico PVE-2 eth0 ↔ ADvIOS-9b Gi0/3 y se creó PVE-2 eth0 ↔ AccvIOS-1 adapter 8 (runtime Gi2/0); el puerto quedó en acceso VLAN 115 y se guardó la configuración.

Decisión corregida y asentada: `WIN-MGMT-HQ-01` y `WIN-MGMT-BR-01` son appliances QEMU independientes dentro de GNS3, no VMs de PVE. Se creó la plantilla `Windows 10 Client LTSC 2021` con la ISO indicada y disco base `empty30G.qcow2`; ambos appliances quedaron detenidos y conectados a ADvIOS-1 Gi0/0/VLAN 90 y AccvIOS-1 Gi0/0/VLAN 110. Las VMs PVE 104 y 105, creadas bajo la interpretación anterior, fueron retiradas después de comprobar que estaban detenidas y sin instalación de SO.

## Resultado

S2.3 queda **Aprobado**. El inventario real contiene DC1/FS-HQ en PVE-1/HQ y DC2/ZBX-1 en PVE-2/BRANCH. Los clientes Windows son appliances QEMU GNS3 independientes, con ISO, recursos y enlaces VLAN comprobados. Todos los appliances y VMs quedan detenidos; no se declara instalación completada de Windows cliente, AD, SMB ni Zabbix.

## Rollback

La corrección sí aplicó rollback de la interpretación anterior: se retiraron las VMs PVE 104/105, ambas detenidas y sin SO instalado. Para revertir la decisión actual, detener los appliances, retirar únicamente los enlaces `3795d122-24f4-44a1-9546-0e566f76d482` y `625ab9aa-5427-4268-b399-28959dbc6608`, restaurar ADvIOS-1 Gi0/0 y AccvIOS-1 Gi0/0 a su preestado, y eliminar los nodos GNS3 sólo después de conservar su configuración. No recrear 104/105 como clientes PVE.
