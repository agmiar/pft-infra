# Incidente S3.1 — DC2 sin IP/servicios en VLAN 115

**Fecha:** 2026-09-20 (UYT, UTC-03:00)  
**Tarea:** S3.1  
**Estado al corte inicial:** Bloqueado.

> Vigencia: este incidente describe el aislamiento observado el 2026-09-20 y queda como antecedente histórico. DC2 fue revalidado posteriormente desde ZBX-1; ver `evidencias/S5/2026-10-12_validacion_evento_4625_DC2.md`.

## Síntoma

Después de iniciar DC2/102, la VM permanece `running`, la NIC virtual tiene MAC `BC:24:11:13:35:71` y el switch aprende esa MAC en `AccvIOS-1 Gi2/0`, VLAN 115. Sin embargo, `192.168.115.12` no responde ICMP ni TCP/53, /389, /445 o /5985 desde Alpine. Un reintento posterior a las `2026-09-20T08:29:58+00:00` volvió a observar `100%` de pérdida y timeouts TCP/53, /389 y /445.

## Impacto

No se puede ejecutar la revalidación interna de DC2 ni comprobar DNS cruzado, replicación AD, Global Catalog, FSMO o tiempo. S3.1 permanece Bloqueada.

## Evidencia

- `2026-09-20_S3.1_PVE_post.txt`: DC2/102 `running`, PVE-2 `vmbr1` y ruta de gestión correctas.
- `2026-09-20_S3.1_AD-DNS_prueba.md`: pruebas de conectividad fallidas hacia `192.168.115.12`.
- `AccvIOS-1 Gi2/0`: `connected`, acceso VLAN 115, MAC de DC2 aprendida.
- `DistvIOS-1`: no hay ARP para `192.168.115.12` tras el arranque.
- `qm agent 102`: `QEMU guest agent is not running`.

## Causa aún no determinada

No se inventa una causa. Las hipótesis comprobables son: Windows no terminó el arranque, la IP interna conserva el direccionamiento anterior, la NIC del invitado no está configurada o el servicio de red/AD todavía no está disponible.

## Rollback aplicado

Ninguno. Sólo se iniciaron las VMs 101/102 después de capturar preestado; no se modificaron IP, ACL, OSPF, bridges, DNS ni AD.

## Condición de reanudación

Acceder a la consola de Windows DC2 con una credencial administrativa autorizada y capturar `hostname`, `ipconfig /all`, estado de NIC, DNS configurado y hora. Si DC2 no tiene la IP `192.168.115.12/27`, corregirla como cambio separado con pre/post y rollback antes de reintentar S3.1. No reutilizar `192.168.50.13` por inferencia.
