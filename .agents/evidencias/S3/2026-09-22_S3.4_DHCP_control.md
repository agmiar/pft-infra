# S3.4 — DHCP, exclusiones, DNS y relay

**Fecha:** 2026-09-22  
**Estado:** Aprobado  
**Equipo ejecutor:** operador único del laboratorio  
**Alcance:** CorevIOS-1, DistvIOS-1, DistvIOS-2 y cliente de prueba Alpine-SSHClient-1.

## Objetivo y precondiciones

Se verificaron y completaron los scopes DHCP para las VLAN del plan, exclusiones de direcciones, gateway virtual, DNS del dominio y relays de BRANCH. S3.1–S3.3 estaban verificadas antes de iniciar.

No se registran contraseñas ni secretos.

## Cambios y decisiones

1. El preestado mostró 13 pools en CorevIOS-1: `VLAN10`, `VLAN20`, `VLAN30`, `VLAN40`, `VLAN60`, `VLAN90`, `BRANCH110`, `BRANCH115`, `BRANCH120`, `BRANCH130`, `BRANCH140`, `BRANCH150` y `BRANCH160`.
2. Las exclusiones existentes preservan gateways, direcciones de infraestructura y extremos altos de cada red.
3. Los pools ya tenían gateway virtual, `domain-name pft.test` y DNS primario `192.168.50.12`.
4. Se corrigió en los 13 pools el DNS secundario incorrecto `192.168.50.13` por el DC2 real `192.168.115.12`.
5. DistvIOS-1 y DistvIOS-2 conservaron los siete `ip helper-address 192.168.50.2`, uno por cada SVI BRANCH 110/115/120/130/140/150/160.
6. Se guardó CorevIOS-1 con `write memory`.

## Evidencia real y aceptación

La evidencia está en [2026-09-22_S3.4_DHCP_prueba.txt](2026-09-22_S3.4_DHCP_prueba.txt). La prueba runtime usó Alpine-SSHClient-1 conectado a VLAN 90:

- `udhcpc` obtuvo `192.168.90.11/27` desde `192.168.90.2`.
- El gateway quedó `192.168.90.1`.
- El binding de CorevIOS-1 mostró `192.168.90.11`, estado `Active`, interfaz `Vlan90` y lease de 86400 segundos.
- Después de la prueba se liberó el lease y se restauró Alpine a `192.168.90.10/27` estática.

Resultado: S3.4 aprobado con configuración persistida, relays verificados y concesión DHCP real.

## Cómo consultar

En CorevIOS-1:

```text
show ip dhcp pool
show ip dhcp binding
show running-config
```

En DistvIOS-1 y DistvIOS-2:

```text
show running-config
```

En un cliente de prueba Linux:

```sh
udhcpc -i eth0 -n -q -t 3
ip -br addr
ip route
```

## Demostración en vivo

1. En CorevIOS-1, mostrar `show ip dhcp pool` y ubicar los 13 pools.
2. Mostrar en la configuración de un pool `dns-server 192.168.50.12 192.168.115.12` y `domain-name pft.test`.
3. En DistvIOS-1, mostrar un SVI BRANCH con `ip helper-address 192.168.50.2`; repetir en DistvIOS-2 si se requiere demostrar redundancia.
4. En un cliente de VLAN 90, ejecutar renovación DHCP y mostrar IP, gateway y binding activo.
5. Restaurar la IP estática sólo si el cliente de demostración es Alpine-SSHClient-1.

## Rollback

Restaurar únicamente los comandos DNS secundarios preexistentes en los 13 pools si se demuestra que el cambio rompe una dependencia; conservar los pools, exclusiones y relays, y guardar nuevamente. Para el cliente de prueba se aplicó rollback local de la IP DHCP a `192.168.90.10/27` estática.
