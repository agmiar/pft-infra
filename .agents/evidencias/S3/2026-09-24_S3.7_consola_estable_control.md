# S3.7 — consola estable y reproducible de los clientes Windows

**Fecha:** 2026-09-24 03:51 (America/Montevideo)  
**Estado:** Aprobado para el subalcance “consola estable”  
**Tarea:** S3.7  
**Ejecutor:** operador único del laboratorio  
**Equipos:** WIN-MGMT-HQ-01 y WIN-MGMT-BR-01

## Objetivo

Dejar un canal de administración gráfica que sobreviva al reinicio de cada cliente y que pueda comprobarse sin depender de la interacción VNC directa de GNS3. Se eligió RDP/TCP 3389 porque es nativo de Windows, no requiere un appliance adicional y permite reproducir la demostración desde una red de gestión.

La consola VNC de GNS3 queda como canal de recuperación/arranque. No se la declara consola estable: durante la intervención su entrada interactiva no fue suficientemente reproducible.

## Precondiciones y respaldo

- Las dos VMs estaban detenidas antes de crear el punto de recuperación y modificar la configuración persistente.
- Se creó el snapshot QEMU `pre-rdp-console-20260924` para cada disco de cliente antes de la habilitación.
- Se conservó el estado de GNS3; no se modificó la tabla de direccionamiento Excel en esta intervención.
- No se registran contraseñas, tickets ni claves.

## Implementación real

En cada cliente, desde una consola administrativa de Windows, se ejecutaron las siguientes acciones con la credencial autorizada suministrada en tiempo de ejecución:

```cmd
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fDenyTSConnections /t REG_DWORD /d 0 /f
netsh advfirewall firewall add rule name=PFT-RDP-MGMT dir=in action=allow protocol=TCP localport=3389 remoteip=192.168.90.0/27,192.168.110.0/27
sc config TermService start= auto
net start TermService
```

Resultados observados en HQ y BR:

- Registro: `The operation completed successfully.`
- Firewall: `Ok.`
- Servicio: `[SC] ChangeServiceConfig SUCCESS`.
- Inicio del servicio: `The requested service has already been started.`; esto confirma que el servicio quedó disponible en la sesión.
- En HQ se fijó además `boot_priority=c` en las propiedades del nodo GNS3 para que el disco Windows sea el dispositivo de arranque persistente. BR ya tenía `boot_priority=c`.

## Aceptación y persistencia

Se reinició cada VM desde la API local de GNS3 y se esperó a que Windows volviera a iniciar. Desde Alpine-SSHClient-1 se verificó:

```sh
nc -vz -w 5 192.168.90.12 3389
nc -vz -w 5 192.168.110.11 3389
```

Ambas pruebas devolvieron `open` antes y después del reinicio. También se comprobó que las VMs quedaron `started` y con `boot_priority=c`. La regla no habilitó SMB ni WinRM: las comprobaciones de control a TCP/445 y TCP/5985 continuaron en timeout desde Alpine.

## Reproducción futura

1. Iniciar el proyecto GNS3 y confirmar que ambos nodos estén `started`.
2. Desde Alpine ejecutar las dos pruebas `nc` anteriores; un resultado `open` confirma reachability hasta el servicio RDP.
3. Desde un equipo ubicado en una de las redes de gestión abrir un cliente RDP contra `192.168.90.12` o `192.168.110.11` y usar una cuenta Windows autorizada. La credencial se introduce sólo en la sesión, nunca en la evidencia.
4. Para demostrar permanencia, reiniciar una VM, esperar el inicio de Windows, repetir `nc` y volver a abrir RDP.
5. Para mostrar la configuración en vivo, consultar `sc qc TermService`, `reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fDenyTSConnections` y `netsh advfirewall firewall show rule name=PFT-RDP-MGMT` desde una consola administrativa.

## Rollback

Rollback lógico, ejecutado sólo si se solicita:

```cmd
netsh advfirewall firewall delete rule name=PFT-RDP-MGMT
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fDenyTSConnections /t REG_DWORD /d 1 /f
sc config TermService start= demand
net stop TermService
```

Si se requiere recuperar el estado anterior completo, detener la VM y restaurar el snapshot QEMU `pre-rdp-console-20260924`. Después verificar que TCP/3389 ya no responda y registrar el resultado.

## Límite del resultado

Esta evidencia aprueba únicamente el canal estable de consola. S3.7 global permanece **Bloqueado** por las pruebas independientes de PVE-1 desde HQ y SMB autenticado permitido/denegado desde ambas estaciones; la consola no sustituye esas pruebas.
