# S3.3 — Renombrado funcional de AD: postestado

**Fecha:** 2026-10-14  
**Estado:** Aprobado  
**Equipo ejecutor:** operador único del laboratorio  
**Alcance:** DC1-PFT y DC2-PFT, dominio `pft.test`.

## Objetivo

Eliminar las denominaciones funcionales que no corresponden al entorno actual y alinearlas con la topología vigente: Docentes, Estudiantes y Lab-IT.

## Cambios ejecutados

| Antes | Después |
|---|---|
| `OU=Finanzas,OU=Usuarios-PFT` | `OU=Docentes,OU=Usuarios-PFT` |
| `OU=RRHH,OU=Usuarios-PFT` | `OU=Estudiantes,OU=Usuarios-PFT` |
| `OU=Operaciones,OU=Usuarios-PFT` | `OU=Lab-IT,OU=Usuarios-PFT` |
| `GG-Finanzas` | `GG-Docentes` |
| `GG-RRHH` | `GG-Estudiantes` |
| `GG-Operaciones` | `GG-Lab-IT` |
| `DL_FS_Finanzas_RW` | `DL_FS_Docentes_RW` |
| `DL_FS_RRHH_RW` | `DL_FS_Estudiantes_RW` |
| `DL_FS_Operaciones_RW` | `DL_FS_Lab-IT_RW` |
| `fin01`–`fin04` | `doc01`–`doc04` |
| `rrhh01`–`rrhh04` | `est01`–`est04` |
| `ops01`–`ops04` | `lab01`–`lab04` |

Se conservaron las membresías y los SID de los objetos mediante renombrado de AD. Las ACLs que referencian los grupos de recursos no se sustituyeron. Los nombres de los shares SMB no se cambiaron para no romper rutas existentes.

## Verificación real

- DC1-PFT muestra las tres nuevas OUs, los tres grupos globales y los tres grupos de recursos.
- Cada grupo global contiene sus cuatro usuarios renombrados.
- Cada grupo `DL_FS_*_RW` contiene el grupo global correspondiente.
- Las GPO siguen enlazadas a `OU=Usuarios-PFT`, `OU=Equipos-PFT` y `OU=Clientes,OU=Equipos-PFT`; el renombrado de OUs no eliminó esos vínculos.
- `repadmin /syncall DC1-PFT /A /e /d /P` terminó con `LastTaskResult = 0`.
- DC2-PFT confirma `Docentes`, `Estudiantes`, `Lab-IT`, los grupos renombrados y usuarios `doc01`, `est01` y `lab01`. Las OUs antiguas `Finanzas`, `RRHH` y `Operaciones` no están presentes en la ruta de usuarios.

## Limitación

Los grupos de gestión heredados `GG_MGMT_PVE_ADMINS`, `GG_MGMT_USERS`, `GG_DB_ADMINS` y `GG_ZABBIX_ADMINS` permanecen sin miembros porque no se definió una autorización para asignar personas. No se modificaron ni se eliminaron.

La consulta directa de `Get-SmbShareAccess` contra FS-HQ no respondió por WinRM durante esta ventana. No se declara una nueva lectura de ACL; la continuidad se sustenta en que el renombrado de grupos conserva sus SID, las membresías AGDLP fueron verificadas después del cambio y los shares no fueron renombrados.

## Rollback

Restaurar los nombres anteriores de OUs, grupos y cuentas mediante `Rename-ADObject`, `Set-ADGroup` y `Set-ADUser`, conservando los mismos SID. Los nombres de los shares no requieren rollback porque no fueron modificados.
