# S3.6 — FS-HQ y shares SMB por área con AGDLP

**Fecha de implementación:** 2026-09-23  
**Estado de aceptación:** Bloqueado  
**Equipo ejecutor:** operador único del laboratorio  
**Alcance:** VM 103 FS-HQ en PVE-1.

## Objetivo y precondiciones

Implementar un servidor de archivos Windows unido a `pft.test`, aplicar el modelo AGDLP para cinco áreas y publicar shares SMB con permisos verificables. La implementación del servidor quedó realizada; la aceptación integral permanece bloqueada hasta probar desde clientes HQ y BRANCH.

## Acciones reales ejecutadas

1. Se corrigió el bus del disco de la VM 103 de SCSI a SATA, conservando el mismo volumen `local-lvm:vm-103-disk-0`; no se borró ni recreó el disco.
2. Se completó Windows Server 2022 Standard Evaluation Desktop Experience.
3. Se fijaron `FS-HQ`, `192.168.50.18/27`, gateway `192.168.50.1` y DNS `192.168.50.12`/`192.168.115.12`.
4. Se instaló `FS-FileServer`; el resultado observado fue `Success=True`, `Restart Needed=No`, `Exit Code=Success`.
5. Se unió FS-HQ a `pft.test` y se verificó con `whoami`, `hostname`, `Get-CimInstance Win32_ComputerSystem` que el equipo pertenece al dominio.
6. Se instalaron las herramientas RSAT-AD-PowerShell necesarias para administrar grupos.
7. Se crearon los grupos locales de dominio: `DL_FS_Administracion_RW`, `DL_FS_Finanzas_RW`, `DL_FS_RRHH_RW`, `DL_FS_TI_RW` y `DL_FS_Operaciones_RW`.
8. Se aplicó AGDLP: `GG-Administracion`, `GG-Finanzas`, `GG-RRHH`, `GG-TI` y `GG-Operaciones` fueron agregados a su grupo local de dominio correspondiente.
9. Se crearon `C:\Shares\Administracion`, `Finanzas`, `RRHH`, `TI` y `Operaciones`.
10. Se publicaron los cinco shares SMB con acceso `Change` para el grupo local de dominio del área y `Full` para `PFT\GG-Administradores`.
11. Se aplicaron ACL NTFS con herencia deshabilitada: `SYSTEM` y administradores locales con control total; grupo local de dominio del área con modificación.
12. Se verificó `Get-SmbShareAccess` e `icacls` en las cinco áreas. Los cinco comandos ACL terminaron con `Successfully processed 1 files; Failed processing 0 files`.

## Resultado real

La implementación del servidor, grupos AGDLP, shares y ACL quedó completada y verificada localmente en FS-HQ. No se declara todavía la aceptación de S3.6 porque faltan las pruebas desde una estación HQ y una estación BRANCH: acceso autorizado, acceso denegado y persistencia del acceso tras reinicio/login.

## Cómo consultar

En FS-HQ, con PowerShell administrativo:

```powershell
hostname
whoami
Get-CimInstance Win32_ComputerSystem | Select-Object Name,Domain,PartOfDomain
Get-NetIPConfiguration
Get-WindowsFeature FS-FileServer
Get-ADGroup -Filter 'Name -like "DL_FS_*"' | Select-Object Name,GroupScope,GroupCategory
Get-ADGroupMember DL_FS_Administracion_RW
Get-SmbShare -Name Administracion,Finanzas,RRHH,TI,Operaciones
Get-SmbShareAccess -Name Administracion,Finanzas,RRHH,TI,Operaciones
icacls C:\Shares\Administracion
```

## Rollback

Si una prueba de permisos falla, retirar únicamente los cinco shares y las ACL creadas, conservar el rol, la VM, el disco, la red y los grupos para diagnóstico. No se debe borrar el volumen ni los objetos AD durante la demostración.

## Condición de reanudación

Acceso operativo simultáneo a un cliente HQ y uno BRANCH, con conectividad SMB hacia `192.168.50.18`, para completar las pruebas cruzadas. La credencial administrativa fue restablecida de forma autorizada y quedó persistente; no se documentan secretos.
