## Acceso administrativo SSH

Desde `AlpineSSHClient-1`, el acceso administrativo previsto es:

```bash
ssh root@192.168.50.10   # PVE-1
ssh root@192.168.50.11   # PVE-2
```

Si el servicio SSH de un PVE no está activo, habilitarlo localmente en ese nodo y volver a probar:

```bash
systemctl enable --now ssh
```

No registrar contraseñas ni credenciales en la evidencia. Esta sección documenta el procedimiento; una conexión SSH efectiva debe aportarse como salida real si se desea acreditar la prueba de acceso.

## Rollback

Antes de persistir cambios, conservar la configuración anterior de los puertos y mantener los PVE desconectados. Ante puerto/VLAN incorrecto, conflicto de IP o conectividad anómala: apagar el appliance afectado, retirar o restaurar el puerto al estado preexistente y conservar las salidas de diagnóstico. No crear clúster ni VMs definitivas.
