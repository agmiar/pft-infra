# Control operativo P3.1–P3.5 — ACL funcional por SVI

- **Fecha de inicio:** 2026-09-23
- **Estado:** Pendiente
- **Objetivo:** Instanciar, adjuntar y validar las ACL `PFT_*` en ambos Core conforme a `.agents/ACL_MATRIZ_Y_RUNBOOK.md`, sin alterar `NAT_INSIDE` y sin presentar la ACL SVI como control de tráfico local de VLAN 50.

## Precondiciones

1. Captura real del preestado de ambos Core: ACL existentes, adjuntos por SVI, máscara/OSPF de VLAN 50 y HSRP.
2. IP real de `WebUbuntuServer-1` en VLAN 100 para sustituir el marcador `<IP_WEB_DMZ>` (confirmada por P1.3 como `192.168.100.6/29`; no se duplicará como evidencia nueva hasta contar con la consola activa).
3. Acceso autenticado y privilegiado a ambas consolas Core para ejecutar los `show`, cargar ACL y, si procede, restaurar rollback.
4. Fuentes disponibles para pruebas positiva y negativa definidas en el runbook.

## Acciones y resultados reales

- Se leyó completo el runbook ACL aprobado.
- La API local de GNS3 confirmó que `CorevIOS-1`, `CorevIOS-2` y `WebUbuntuServer-1` estaban detenidos después del reinicio de la laptop.
- Se iniciaron los tres nodos por API GNS3. Aún no se captura el preestado del IOS ni se modifica ninguna ACL.
- Los logs de arranque muestran HSRP y la vecindad OSPF VLAN 90 restablecidos; ambos Core quedaron en `User Access Verification` solicitando contraseña.
- Se autenticaron ambas consolas; CorevIOS-1 tiene privilegio 15 directo y CorevIOS-2 elevó con `enable`. Se capturaron los adjuntos reales y el estado HSRP/OSPF previo.
- La primera carga P3.2 fue parcial por la consola serie; se aplicó rollback completo sin afectar adjuntos. Ver `2026-09-23_P3.2_CorevIOS_incidente.md`.
