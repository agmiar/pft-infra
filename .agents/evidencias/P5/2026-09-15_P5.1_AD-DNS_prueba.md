# P5.1 — Resultado de aceptación de AD DS y DNS

**Fecha:** 2026-09-15 (UYT)  
**Estado:** Aprobado  
**Evidencias:** [preestado inicial](2026-09-14_P5.1_AD-DNS_pre.txt), [inventario](2026-09-15_P5.1_AD-DNS_inventario.md), [postestado](2026-09-15_P5.1_AD-DNS_post.txt), [control](2026-09-15_P5.1_AD-DNS_control.md), [P1.3](../P1/2026-09-15_P1.3_WebUbuntuServer-1_prueba.md).

## Objetivo y criterio del Plan Unificado

Crear DC1 con AD DS/DNS para `pft.test`, agregar DC2 como DC/DNS en el otro PVE, configurar IP/DNS cruzado y verificar la réplica inicial. Tras validar ambos DNS, configurar el frontend con .12/.13 y demostrar la resolución efectiva de `web.pft.test` para cerrar la dependencia DNS de P1.3.

## Resultado real

Los criterios mínimos del Plan Unificado se cumplieron en el cierre registrado a las 12:48 UYT. DC1-PFT (.12/27) está en PVE-1 y DC2-PFT (.13/27) en PVE-2; ambos tienen gateway .1, AD DS/DNS y DNS cruzado. Las zonas `pft.test` y `_msdcs.pft.test` son integradas con AD. DCDIAG final pasó en ambos controladores; `repadmin /replsummary` mostró 0/5 fallas por dirección y error 0; las consultas SRV directas a ambos DNS devolvieron los dos controladores por puerto 389.

WebUbuntuServer-1 usa DNS .12/.13 en ens3; `resolvectl query web.pft.test` resolvió la IP real 192.168.100.6. Tras P4.5, se restauró DC1 a `running`, ambos PVE volvieron a 3/3 con QDevice y las consultas SRV directas a ambos DNS siguieron devolviendo DC1 y DC2.

## Salvedades y límites

- No se configuró ni verificó un forwarder corporativo/de laboratorio ni se probó resolución DNS externa. El upstream no quedó acreditado; no se afirma forwarding.
- DC2 presentó una falla RReg transitoria en el primer DCDIAG mientras convergía; el reintento final pasó. También se conservaron el NXDOMAIN inicial tras crear el registro web, una consulta SRV local que mostró solo DC1 y deltas de replicación sin errores.
- La condición de VLAN 100 se respalda con inventario histórico del 2026-08-30; no se recapturó el puerto de switch en esta sesión. No se afirma HTTP/HTTPS.
- Las omisiones manuales P4.3 siguen vigentes: P4T-PVE2, prueba VM-a-VM y aprendizaje MAC de ambas VMs no se ejecutaron.
- No se iniciaron P5.2 ni P5.3. No se incluyen contraseñas, claves privadas, tokens ni tickets.

## Acciones, resultado y rollback

Se revisaron el postestado y la matriz de aceptación originales y, tras completar P4.5, se revalidaron por consola quorum 3/3, servicios PVE, ejecución de DC1/DC2 y respuestas SRV directas. No se aplicó rollback funcional porque AD/DNS y la resolución del frontend cumplieron el criterio. Se conservan VMs/discos, el registro A `web` requerido para P1.3 y el DNS del frontend. No se improvisará una democión del bosque ni se borrarán discos.
