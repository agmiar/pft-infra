# Incidente de acceso a PVE desde LaptopUbuntu — P5.2

**Fecha:** 2026-09-17; hora no informada.  
**Tarea:** P5.2 — acceso administrativo para completar la configuración y sus verificaciones.  
**Estado:** Bloqueado.  
**Fuente:** diagnóstico reportado por el operador; no ejecutado por el agente.

## Síntoma

Las consultas de ruta reportadas para PVE-1 (192.168.50.10) y PVE-2 (192.168.50.11) usan el gateway Wi-Fi 192.168.1.1, la interfaz wlp0s20f3 y la IP de origen 192.168.1.190. El intento HTTPS reportado contra PVE-1 TCP/8006 agotó el tiempo aproximadamente a los cuatro segundos y devolvió HTTP 000.

La ventana de Cloud de GNS3 mostró enp4s0 bajo “Ethernet interfaces”. El operador indicó que ip -br addr show enp4s0 mostraba down. No se recibió la línea completa ni la salida de ip link show; tampoco se confirmó si enp4s0 estaba asignada a Cloud o era sólo una interfaz listada.

## Impacto

Desde LaptopUbuntu no quedó comprobado el acceso a la GUI de PVE por TCP/8006. Estos resultados describen el camino desde la laptop; no prueban que PVE esté detenido ni identifican por sí solos si el límite está en el router Wi-Fi, el mapeo/enlace de Cloud, un filtro o el servicio de PVE. No se probó autenticación en PVE ni en Windows.

P5.2 ya tenía otros bloqueantes registrados: falta de una sesión administrativa Windows disponible para continuar las escrituras/verificaciones y decisiones pendientes sobre miembros de los grupos GG, valores/alcance/filtros de las GPO y si se requiere la zona inversa/PTR de VLAN 100. Este incidente no resuelve ni sustituye esos bloqueantes.

## Rollback

No aplica. Sólo se reportaron comprobaciones de lectura y no se informó ningún cambio de red, interfaz, Cloud, PVE, GNS3, ACL o AD.

## Condición de reanudación

Confirmar la salida completa de ip link show enp4s0, si Cloud la tiene asignada (no sólo listada) y a qué conexión de PVE llega. Establecer un camino autorizado de LaptopUbuntu a la administración PVE; verificar TCP/8006 antes de usar la GUI. Para continuar P5.2 también hace falta recuperar un canal administrativo de Windows y resolver las decisiones de grupos, GPO y reversa VLAN 100. No repetir credenciales fallidas ni exponer la API GNS3 o puertos VNC.
