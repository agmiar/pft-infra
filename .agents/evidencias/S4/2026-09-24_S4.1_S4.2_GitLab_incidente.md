# S4.1/S4.2 — incidente de acceso a los repositorios locales

- **Fecha:** 2026-09-24
- **Estado:** Bloqueado
- **Objetivo:** disponer localmente del proyecto API Spring y del frontend React sin modificar los repositorios remotos.

## Síntoma

Los dos `git ls-remote` HTTPS solicitaron autenticación GitLab y no existía una credencial utilizable en el equipo. La conexión SSH al GitLab por TCP/22 tampoco resultó disponible. La interfaz web de GitLab mostró la pantalla de inicio de sesión LDAP.

## Acciones realizadas

- Se intentó lectura remota de ambos repositorios con Git, sin ejecutar push ni modificar ramas.
- Se verificó la pantalla de autenticación de GitLab desde el navegador de la aplicación.
- Se inició WebUbuntuServer-1 por GNS3 y se verificó su IP DMZ real `192.168.100.6/29`.
- Se instaló Docker Engine y Compose v2 en WebUbuntuServer-1 para preparar el despliegue local.
- Docker quedó habilitado y activo como servicio; Compose v2 quedó disponible para el usuario `student`.
- La interfaz NAT temporal, el proxy de instalación y las rutas auxiliares fueron retirados al terminar la preparación; la interfaz DMZ no se reemplazó.
- No se clonó ni se alteró ningún repositorio remoto; no se generó una configuración ficticia para la API.

## Resultado

S4.1 y S4.2 quedan **Bloqueados** hasta disponer de una de estas condiciones:

1. credencial exacta de GitLab/LDAP autorizada para lectura, o
2. copias locales de ambos repositorios en el host.

No se debe reutilizar la contraseña de Windows, WebUbuntuServer o switches como credencial GitLab. La decisión mantiene la separación de secretos y evita modificar remotamente los proyectos.

## Qué falta ejecutar al desbloquear

- Clonar ambos repositorios sólo a un directorio local de trabajo.
- Inspeccionar sus `docker-compose`, variables y endpoints reales.
- Levantar PostgreSQL no publicado, API y frontend en WebUbuntuServer-1.
- Añadir únicamente la integración frontend necesaria para consumir el JWT existente; no cambiar la lógica de autenticación de Spring Security sin evidencia del código.
- Probar login correcto, login fallido, JWT/RBAC y conectividad desde la DMZ.

## Rollback

No aplica a repositorios: no hubo cambios. Si se continúa, los clones locales deben conservarse fuera de las ramas remotas y cualquier ajuste permanecer en archivos locales sin push.
