# S4.3 — BKP-1 y backup manual por hito

- **Fecha:** 2026-09-24
- **Estado:** Bloqueado en la verificación final de System State
- **Objetivo:** implementar un destino de backup austero, probar System State de DC1 y dejar tres puntos verificables de FS-HQ.

## Diseño y austeridad

Se creó un único contenedor Docker GNS3 `BKP-1` con Samba, conectado a VLAN160. Se reutilizó la red y el volumen persistente de GNS3; no se creó una VM adicional ni un appliance pesado. El servicio expone únicamente SMB en la red de backup y conserva los datos en el volumen persistente del proyecto.

Dirección: `192.168.160.10/27`; gateway HSRP: `192.168.160.1`; share: `BKP`.

## Implementación real

- Imagen local `pft/bkp-samba:1.0` construida desde Alpine.
- Servicio Samba iniciado y escuchando en TCP/445.
- Cuenta técnica de backup creada en runtime; la credencial no se registra en evidencias.
- Volumen persistente configurado en la propiedad `extra_volumes` de GNS3 para `/srv/bkp`.
- VLAN160, SVI HSRP y ACL documentadas en S1.5.

## Backup de DC1

En DC1 se habilitó el componente Windows Server Backup, se instaló la herramienta `wbadmin` desde WinSxS y se ejecutó un System State backup al share SMB de BKP-1 como proceso del sistema. El árbol persistente generado quedó bajo:

`WindowsImageBackup/DC1-PFT/Backup 2026-09-24 181305/`

La evidencia post registra la salida final del proceso y el tamaño/estructura observados en el volumen; no se incluye ninguna contraseña ni token.

## Backup por hitos de FS-HQ

Se conservaron tres puntos de archivo en `FS-HQ/2026-09-24/`:

- `point-01`: estado con el archivo controlado de restauración.
- `point-02`: estado después de eliminar el archivo; las cinco tar fueron verificadas sin el archivo.
- `point-03`: estado posterior a la restauración; Administración contiene nuevamente un archivo.

Cada punto conserva las cinco áreas SMB: Administracion, Finanzas, RRHH, TI y Operaciones. Se verificaron tamaños, presencia de los tar y conteo de archivos.

## Aceptación

Los tres puntos de FS-HQ son reproducibles desde el volumen persistente y quedan comprobados. El VHDX de DC1 se generó y dejó de crecer con una estructura VHDX válida, pero la salida final de `wbadmin` no pudo recuperarse porque el comando remoto quedó esperando la limpieza interactiva de `net use`; además, DC1 requirió un reinicio controlado para recuperar su estado de red. Por trazabilidad, S4.3 queda **Bloqueado** hasta ejecutar `wbadmin get versions` desde DC1 o una consola equivalente y observar la versión final. No se afirma HA automática ni backup incremental continuo.

## Rollback

Detener BKP-1, desmontar el volumen sólo después de preservar su copia y retirar el nodo/enlace VLAN160. La restauración de DC1 debe usar `wbadmin` en entorno controlado; no se permite revertir el controlador de dominio mediante snapshot como sustituto de System State.
