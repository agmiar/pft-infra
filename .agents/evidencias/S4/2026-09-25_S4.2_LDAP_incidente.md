# S4.2 — LDAP real contra Active Directory

Fecha: 2026-09-25
Estado: Aprobado

## Objetivo

Permitir login de SIENEP Web con usuarios reales de `pft.test`, conservando Spring Security, emisión JWT, cookie de sesión y RBAC de aplicación.

## Precondiciones

- DC1-PFT accesible por LDAP TCP/389 desde WebUbuntuServer-1.
- Backend Spring Boot y frontend disponibles.
- Los secretos se mantienen sólo en runtime y no se incluyen en evidencias.

## Implementación

1. El frontend conserva el JSON existente y presenta el campo `Usuario LDAP o correo`, por lo que acepta UPN o identificador de dominio.
2. El backend incorpora `spring-security-ldap` y un proveedor JNDI de bind simple contra Active Directory. El proveedor se ejecuta antes del proveedor local, sin eliminar `UserAuthProvider`, JWT ni RBAC.
3. Se admite el mapeo de identificadores `usuario@pft.test` y `PFT\\usuario` hacia el principal UPN del dominio.
4. La imagen desplegada es `pft/sienep-api:2026-09-25-ldap-jndi`; la configuración runtime mantiene LDAP habilitado, URL interna y mapeo de `administrator` al usuario de aplicación.

## Pruebas reales y consulta

- Bind LDAP directo contra DC1: UPN y formato down-level devolvieron resultado LDAP 0.
- Login API con UPN: HTTP 200; respuesta con `token`, `expiresIn`, `tipo` y cookie.
- Login API con `pft.test\\administrator`: HTTP 200; respuesta con token y cookie.
- Contraseña inválida: HTTP 401.
- Consulta reproducible: abrir `/login`, ingresar cualquiera de los dos formatos válidos, observar HTTP 200 y llamar un endpoint protegido con el JWT. Repetir con contraseña inválida y observar HTTP 401.

## Demostración en vivo

1. Abrir SIENEP Web y mostrar el campo `Usuario LDAP o correo`.
2. Autenticar con `administrator@pft.test`.
3. Cerrar sesión y autenticar con `PFT\\administrator`.
4. Mostrar cookie/token y un recurso protegido.
5. Repetir con contraseña inválida y mostrar HTTP 401.

## Rollback

Volver a la imagen backend anterior y al ZIP original del frontend; conservar `LDAP_ENABLED=false` sólo como contingencia. No se aplicó rollback.

## Limitaciones

Se usa LDAP simple interno en TCP/389 dentro del laboratorio; LDAPS/certificados quedan fuera del alcance acordado. El token JWT y el RBAC de la aplicación permanecen activos.
