# Incidente S4.3 — salida remota de wbadmin sin cierre verificable

- **Fecha:** 2026-09-24
- **Estado:** Bloqueado
- **Síntoma:** el VHDX de System State dejó de crecer, pero el comando remoto quedó retenido al ejecutar `net use ... /delete`; la consola no devolvió la salida final de `wbadmin`.
- **Impacto:** no se puede afirmar desde la consola que Windows haya registrado la versión final del backup, aunque el destino conserva un VHDX VHDX-Extended válido, metadatos, catálogo y `BackupSpecs.xml`.
- **Acción de contención:** se retiró el contenedor de herramientas temporal, se conservó el volumen persistente y se reinició DC1 de forma controlada mediante QMP/Proxmox para no dejar el proceso remoto reteniendo la VM. Al cierre de esta captura, TCP/445 y TCP/53 de DC1 todavía no habían vuelto a responder.
- **Rollback aplicado:** no se borró ni sobrescribió el árbol `WindowsImageBackup/DC1-PFT`; los tres puntos FS-HQ permanecen intactos.
- **Condición de reanudación:** recuperar primero SMB/DNS de DC1; luego ejecutar `wbadmin get versions -backupTarget:\\192.168.160.10\BKP` desde una consola administrativa y anexar la salida. Si no aparece una versión, repetir el System State con una limpieza no interactiva (`net use ... /delete /y`).

No se registran credenciales.
