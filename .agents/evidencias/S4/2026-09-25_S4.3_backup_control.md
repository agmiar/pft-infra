# S4.3 — BKP-1: control y evidencia

Fecha: 2026-09-25
Estado: Aprobado

## Objetivo

Implementar BKP-1 como repositorio SMB austero y conservar puntos verificables de System State de DC1 sin destruir antecedentes.

## Precondiciones

- BKP-1 encendido en `192.168.160.10/27`.
- Volumen persistente `/srv/bkp` montado.
- No eliminar respaldos ni discos durante la comprobación.

## Acciones ejecutadas y consulta

1. Se verificó SMB TCP/445 y el recurso `BKP`.
2. Se creó/ajustó el usuario técnico `backup` sólo en runtime y se mapeó el recurso desde DC1 con `net use` exitoso.
3. Se ejecutó `wbadmin start systemstatebackup` hacia `\\192.168.160.10\BKP\fresh`; la operación creó `WindowsImageBackup/DC1-PFT/Backup 2026-09-25 130558/`, VHDX de System State, `BackupSpecs.xml`, catálogo y XML de writers.
4. Se conservaron los puntos generados en `/srv/bkp/WindowsImageBackup/DC1-PFT/Backup 2026-09-25 125545/` y `/srv/bkp/fresh/WindowsImageBackup/DC1-PFT/Backup 2026-09-25 130558/`, sin borrado.
5. `du` del repositorio confirmó aproximadamente 698.5 MiB en el árbol histórico y 27.8 MiB en el punto fresh. La estructura y los archivos se verificaron con `docker exec GNS3.BKP-1... find/du`.
6. Consulta reproducible: `nc -vz -w 5 192.168.160.10 445`; `docker exec <contenedor-BKP> du -sh /srv/bkp/*`; desde DC1, `wbadmin start systemstatebackup -backuptarget:\\192.168.160.10\BKP\fresh -quiet`.

## Resultado

BKP-1 quedó operativo como repositorio SMB persistente y contiene el System State recién generado, sus catálogos/XML y los puntos previos. La retención por hitos queda preservada y no se eliminó ningún activo.

## Demostración en vivo

1. Encender BKP-1 y mostrar TCP/445 y el share `BKP`.
2. Mostrar los dos árboles persistidos bajo `/srv/bkp/WindowsImageBackup/DC1-PFT/` y `/srv/bkp/fresh/WindowsImageBackup/DC1-PFT/`.
3. En DC1 ejecutar `wbadmin get versions -backupTarget:\\192.168.160.10\BKP\fresh`.
4. Mostrar `BackupSpecs.xml`, catálogo y VHDX sin exponer credenciales.
5. Conservar el repositorio después de la prueba.

## Rollback

No borrar ningún punto ni VHDX. Si una prueba altera una ruta, eliminar sólo la copia temporal y preservar `/srv/bkp`.

## Limitación

La salida final de `wbadmin get versions` no se capturó en esta sesión porque la consola anidada de PVE-1 no expuso una sesión Windows interactiva estable. Sí se verificó la creación real del VHDX/catálogo y la persistencia del repositorio; la consulta queda preparada para la grabación final.
