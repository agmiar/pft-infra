# Incidente P2.2 — DummyInternet sin mecanismo NAT

- **Fecha:** 2026-08-30
- **Tarea:** P2.2
- **Estado:** Aprobado

## Síntoma

Desde AlpineSSHClient-1 el `traceroute` a `1.1.1.1` alcanza `200.0.0.9` (DummyInternet) y después no recibe respuesta. Una solicitud HTTPS por nombre falla antes por DNS (`wget: bad address 'dl-cdn.alpinelinux.org'`).

## Hallazgo real

En DummyInternet:

```text
/bin/sh: iptables: not found
/bin/sh: nft: not found
net.ipv4.ip_forward = 1
default via 192.168.122.1 dev eth2 metric 225
192.168.122.0/24 dev eth2 scope link src 192.168.122.37
200.0.0.8/30 dev eth0 scope link src 200.0.0.9
```

El host puede reenviar IP, pero no tiene herramienta ni reglas visibles para SNAT/MASQUERADE del tráfico que entra desde la red `200.0.0.0/30` hacia la red NAT GNS3 por `eth2`.

## Impacto

No se puede validar conectividad HTTPS extremo a extremo desde un host interno después de P2.2. La traducción en BorderRouter-1 sí está comprobada, pero no el tramo posterior DummyInternet → NAT GNS3/Internet.

## Evidencia relacionada

- `2026-08-30_P2.2_AlpineSSHClient-1_prueba.txt`
- Salida de DummyInternet aportada por el operador el 2026-08-30.

## Rollback aplicado

Ninguno. Por decisión del operador se conserva P2.2 en ejecución: VLAN 50 `/27`, HSRP, OSPF y NAT de Border no presentan evidencia de ser la causa del incidente.

## Condición de reanudación

Cumplida el 2026-08-30: el operador restauró una imagen o nodo de DummyInternet con `iptables`, configuró eth0 `200.0.0.9/30`, eth1 `200.0.0.13/30`, eth2 DHCP de GNS3 NAT, `ip_forward=1`, cuatro reglas FORWARD y MASQUERADE de las redes `200.0.0.0/30` y `200.0.0.12/30` por eth2. AlpineSSHClient-1 recibió 3/3 respuestas desde `1.1.1.1` y obtuvo HTTP 200 por HTTPS. BorderRouter-1 mostró NAT activo con Hits 100, Misses 0 y traducciones ICMP, DNS y HTTPS.
